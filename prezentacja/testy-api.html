Testy API

Mateusz Krzyzak · API i automatyzacja · ← powrót do strony głównej

10 automatycznych testów API w Playwright (APIRequestContext, bez przeglądarki). Testy mają architekturę warstwową: scenariusz i asercje są oddzielone od wywołań HTTP, danych testowych i zapisu evidence.

Architektura

05_Automation/
├─ tests/api.spec.ts        scenariusze i asercje
└─ api/
   ├─ clients/              BaseClient, AuthClient, RoomClient, MessageClient, BookingClient
   ├─ data/                 builders.ts (buildMessage, buildBooking), dates.ts (wolny termin)
   ├─ endpoints.ts          ścieżki API
   ├─ types.ts              Room, Message, Booking, ApiResult, AuthSession
   └─ index.ts              fixture: api.auth / api.rooms / api.messages / api.bookings
KlientMetody
AuthClientlogin(user, pass), loginAsAdmin() → sesja
RoomClientlist(), get(id), firstListed()
MessageClientcreate(), list(), get(), markRead(), delete(), findByName()
BookingClientlistForRoom(), create(), get(), update(), delete()
  • Asercje tylko w testach – klient nie ocenia wyniku, więc obsługuje przypadki pozytywne i celowo błędne.
  • Evidence automatyczne – każde wywołanie przechodzi przez BaseClient → Audit.
  • Buildery danych – poprawne dane domyślne, test nadpisuje tylko badane pole; unikalny znacznik QA.
  • Asercje miękkie w sekwencjach – w API-09/10 odczyt po ID nie przerywa testu, więc krok PUT i jego potwierdzenie są wykonane i udokumentowane.
